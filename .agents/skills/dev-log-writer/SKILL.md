# Dev Log Writer

## 역할

개발 과정에서 발생한 **문제 해결 과정(트러블슈팅)** 또는 **기술 선택 이유(의사결정)** 를 학습용 문서로 정리한다.

이 스킬의 목적은 "그럴듯한 문서"가 아니라 **본인이 실제로 겪고 판단한 과정을 스스로 되돌아보게 만드는 것**이다. 따라서 부족한 정보를 지어내지 않고, 작성자에게 질문해서 끌어낸다.

## 핵심 원칙

- **지어내지 않는다.** 증상, 원인, 시도한 것, 결정 이유를 모르면 상상해서 채우지 말고 작성자에게 질문한다.
- **근거에 기반한다.** 실제 에러 메시지, 로그, 커밋, 코드, 문서에서 확인할 수 있는 내용을 우선 사용한다.
- **실패도 기록한다.** "시도했지만 안 된 것", "감수한 트레이드오프"처럼 배움이 담긴 부분을 빼지 않는다.
- **작성자의 언어로 남긴다.** 작성자가 설명한 표현을 존중하고, 과장하거나 미화하지 않는다.

## 작업 전 확인

문서를 바로 쓰지 말고 먼저 무엇을 다루는지 확인한다.

- 문제/결정 대상이 코드나 커밋과 관련 있으면 `git log --oneline -n 10`, `git diff`, 관련 파일을 먼저 확인한다.
- 에러 메시지, 로그, 스택트레이스가 있으면 그대로 인용할 수 있게 확보한다.
- 작성에 필요한 핵심 정보가 비어 있으면 아래 정보 수집 질문으로 먼저 물어본 뒤 작성한다.

정보가 충분히 모이기 전에는 템플릿을 억지로 다 채우지 않는다. 확인되지 않은 항목은 `(작성 필요)`로 남긴다.

## 문서 로딩 규칙

이 섹션의 `references/...` 경로는 이 `SKILL.md`가 있는 스킬 디렉터리 기준으로 해석한다.

- `references/trouble-shooting-template.md`
  - 트러블슈팅(문제 해결 과정) 문서를 작성할 때 읽는다.
- `references/decision-record-template.md`
  - 의사결정(기술 선택 이유, ADR) 문서를 작성할 때 읽는다.
- `references/writing-guide.md`
  - 좋은/나쁜 작성 예시, 질문 방식, 흔한 실수를 확인해야 할 때 읽는다.
  - 두 문서 유형 모두에 공통으로 적용된다.

## 작업 모드

### 1. 트러블슈팅 기록 모드

작성자가 "문제 해결 과정 정리해줘", "에러 해결한 거 기록해줘", "삽질 기록 남겨줘", "트러블슈팅 문서 작성해줘"처럼 요청하면 사용한다.

1. `references/trouble-shooting-template.md`를 읽는다.
2. 필요하면 `references/writing-guide.md`를 읽는다.
3. 확보된 근거(에러 메시지, 로그, 커밋, 코드)를 먼저 정리한다.
4. 비어 있는 항목은 "정보 수집 질문 - 트러블슈팅"으로 작성자에게 묻는다.
5. 답변과 근거를 바탕으로 템플릿을 채운다.

**정보 수집 질문 - 트러블슈팅**

- 어떤 상황에서, 무엇을 하려다 문제가 발생했나요?
- 실제로 나타난 증상이나 에러 메시지는 무엇인가요?
- 원인은 무엇이었나요? (아직 모른다면 "원인 미상"으로 둡니다)
- 시도했지만 안 됐던 방법이 있나요?
- 최종적으로 어떻게 해결했나요?
- 이 경험에서 배운 점이나 다음에 다르게 할 점은 무엇인가요?

### 2. 의사결정 기록 모드

작성자가 "왜 이 방식 선택했는지 정리해줘", "기술 선택 이유 남겨줘", "ADR 작성해줘", "의사결정 기록 작성해줘"처럼 요청하면 사용한다.

1. `references/decision-record-template.md`를 읽는다.
2. 필요하면 `references/writing-guide.md`를 읽는다.
3. 결정의 배경(어떤 문제/요구 때문에 선택이 필요했는지)을 먼저 파악한다.
4. 비어 있는 항목은 "정보 수집 질문 - 의사결정"으로 작성자에게 묻는다.
5. 답변을 바탕으로 선택지 비교와 결정 근거를 정리한다.

**정보 수집 질문 - 의사결정**

- 어떤 문제나 요구 때문에 결정이 필요했나요?
- 어떤 선택지들을 고려했나요? (최소 2개)
- 각 선택지의 장단점은 무엇이었나요?
- 최종적으로 무엇을 선택했나요?
- 그 선택을 한 결정적인 이유는 무엇인가요?
- 그 선택 때문에 감수하기로 한 단점(트레이드오프)이 있나요?

## 문서 저장

- 트러블슈팅: `docs/troubleshooting/` 아래 저장을 제안한다. 예: `docs/troubleshooting/결제-웹훅-중복처리.md`
- 의사결정: `docs/decisions/` 아래 저장을 제안한다. 예: `docs/decisions/0001-결제-멱등성-키-전략.md`
- 폴더가 없으면 만들지 여부를 먼저 확인한다.
- 파일명은 날짜나 순번 + 핵심 주제로 짧게 제안한다.

## 금지사항

- 확인되지 않은 증상, 원인, 시도, 결정 이유를 지어내지 않는다.
- 실제로 하지 않은 시도나 검증을 한 것처럼 적지 않는다.
- 실패 과정이나 트레이드오프를 보기 좋게 삭제하지 않는다.
- 작성자에게 확인하지 않은 채 결론을 단정하지 않는다.
- 에러 메시지, 로그, 코드를 실제와 다르게 각색하지 않는다.
