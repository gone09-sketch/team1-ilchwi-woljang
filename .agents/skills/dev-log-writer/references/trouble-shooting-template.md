# Troubleshooting Template

트러블슈팅 문서는 "무슨 일이 있었고, 왜 그랬고, 어떻게 풀었고, 무엇을 배웠는가"가 남게 작성한다.
확인되지 않은 항목은 지어내지 말고 `(작성 필요)`로 남긴다.

## 채우는 순서

1. 확보된 근거(에러 메시지, 로그, 커밋)를 먼저 넣는다.
2. 증상 -> 원인 -> 시도 -> 해결 순서로 사실을 채운다.
3. 마지막에 "배운 점"을 작성자 본인의 말로 정리한다.

## 템플릿

````markdown
# [트러블슈팅] {문제를 한 줄로}

- 작성일: {YYYY-MM-DD}
- 관련 기능/도메인: {예: 결제 웹훅, 로그인}
- 관련 커밋/PR: {있으면}

## 한 줄 요약

{어떤 문제를 어떻게 해결했는지 한 문장}

## 환경

- {예: Spring Boot 4.0.6, Java 21, MySQL 8, 로컬/테스트}

## 문제 상황 (증상)

{무엇을 하려다 어떤 증상이 나타났는가. 관찰된 사실만}

에러 메시지 / 로그:

```text
{실제 에러 메시지나 로그를 그대로 붙여넣기}
```

## 재현 방법

1. {어떤 요청/동작을 하면}
2. {어떤 결과가 나오는지}

## 원인 분석

{왜 이 문제가 발생했는가. 확인된 근거와 함께. 아직 모르면 "원인 미상 + 의심되는 지점"}

## 시도한 것들

| 시도 | 결과 | 왜 안 됐나 |
| --- | --- | --- |
| {방법 1} | 실패 | {이유} |
| {방법 2} | 실패 | {이유} |
| {방법 3} | 성공 | {이유} |

## 해결 방법

{최종적으로 문제를 해결한 방법. 바뀐 코드나 설정이 있으면 핵심만}

## 배운 점 / 다음에 할 것

- {이 경험에서 배운 것}
- {다음에 같은 문제를 피하려면 무엇을 할지}

## 참고 자료

- {문서 링크, 이슈, 블로그 등}
````
