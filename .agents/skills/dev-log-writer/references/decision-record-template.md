# Decision Record Template

의사결정 문서(ADR, Architecture Decision Record)는 "무엇을 고민했고, 어떤 선택지가 있었고, 왜 그것을 골랐고, 무엇을 감수했는가"가 남게 작성한다.

핵심은 **결정 그 자체보다 '이유'와 '감수한 것(트레이드오프)'** 이다. 선택지는 최소 2개 이상 비교한다.
확인되지 않은 항목은 지어내지 말고 `(작성 필요)`로 남긴다.

## 채우는 순서

1. 배경(왜 결정이 필요했는지)을 먼저 적는다.
2. 고려한 선택지를 장단점과 함께 나열한다.
3. 결정과 그 이유를 적는다.
4. 감수한 트레이드오프를 솔직하게 적는다.

## 상태 값

- `제안됨`: 아직 논의 중
- `결정됨`: 채택되어 적용 중
- `변경됨`: 이후 다른 결정으로 대체됨 (대체한 문서 링크)

## 템플릿

```markdown
# [의사결정] {결정 내용을 한 줄로}

- 번호: {0001 같은 순번}
- 작성일: {YYYY-MM-DD}
- 상태: {제안됨 / 결정됨 / 변경됨}
- 관련 기능/도메인: {예: 결제 멱등성, 인증 방식}

## 배경 / 문제

{어떤 문제나 요구 때문에 이 결정이 필요했는가}

## 고려한 선택지

### 선택지 A: {이름}

- 장점: {...}
- 단점: {...}

### 선택지 B: {이름}

- 장점: {...}
- 단점: {...}

### 선택지 C: {이름} (있으면)

- 장점: {...}
- 단점: {...}

## 결정

**{선택한 것}** 을 선택한다.

## 결정 이유

- {결정적이었던 이유 1}
- {결정적이었던 이유 2}

## 감수한 것 (트레이드오프)

- {이 선택 때문에 포기하거나 감수한 단점}

## 결과 / 후속

{적용 후 어떻게 되었는지. 나중에 업데이트해도 됨}

## 참고 자료

- {문서, 이슈, 레퍼런스}
```
