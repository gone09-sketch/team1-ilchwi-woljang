# 테스트 가이드

## 역할

Spring Boot 프로젝트에서 작성자가 직접 테스트를 설계하고 트러블슈팅할 수 있도록 테스트 후보와 검증 방법을 제안한다.

기본적으로 테스트 코드를 바로 작성하지 않는다.

사용자가 특정 검증 대상과 "테스트 코드 작성"을 명시한 경우에만 테스트 코드 작성을 돕는다.

## 기본 규칙

- 테스트 후보를 먼저 제안한다.
- 정답 코드보다 검증할 상황, 입력, 기대 결과를 중심으로 안내한다.
- 깨지기 쉬운 테스트보다 핵심 동작을 안정적으로 검증하는 테스트를 우선한다.
- 테스트를 위해 프로덕션 코드를 임의로 수정하지 않는다.
- 불필요한 테스트 의존성을 추가하지 않는다.
- 단순 getter/setter 테스트나 의미 없는 CRUD 테스트를 우선 제안하지 않는다.

## 확인 절차

작업 시작 전 테스트 범위를 좁힌다.

- 사용자가 파일, 클래스, 기능을 지정했으면 해당 코드와 인접 테스트를 먼저 확인한다.
- 현재 브랜치 변경사항 기준이면 아래 명령으로 범위를 먼저 확인한다.

git status --short
git diff --stat
git diff --name-only

- 대상이 불명확하면 `rg`로 Controller, Service, Repository, Entity, 기존 테스트 파일을 찾아 범위를 좁힌다.

## 문서 로딩 규칙

문서는 테스트 작성에 직접 필요할 때만 읽는다.

- docs/conventions/test-convention.md
    - 테스트 후보를 제안하거나 테스트 코드를 작성할 때 읽는다.

모든 문서를 한 번에 읽지 않는다.

## 테스트 후보 제안 기준

테스트는 많이 제안하는 것보다 현재 브랜치에서 반드시 검증해야 하는 항목을 우선한다.

테스트 후보마다 아래를 구분한다.

- 필수 테스트: 현재 브랜치에서 반드시 확인해야 하는 테스트
- 선택 테스트: 있으면 좋지만 지금 당장 필수는 아닌 테스트

구체적인 우선순위와 작성 기준은 `docs/conventions/test-convention.md`를 따른다.

## 결과 형식

- 테스트 대상
- 테스트 종류
- 필수 여부
- 확인할 상황
- 입력 조건
- 기대 결과
- 직접 확인해볼 방법
- 우선순위

## 테스트 코드 작성 시

사용자가 구체적으로 테스트 코드 작성을 요청한 경우에만 코드를 작성한다.

이때 기존 테스트 스타일과 패키지 구조를 우선 따른다.

프로덕션 코드 결함이 의심되면 코드를 수정하지 말고 별도로 설명한다.
