# Async & Concurrency

## Status

이 문서는 프로젝트 고도화 단계에서 비동기 처리나 동시성 제어가 필요해질 때 작성한다.

현재 단계에서는 비동기 처리 대상과 동시성 문제가 확정되지 않았으므로 구체적인 구현 규칙을 정하지 않는다.

## 작성 전 확인할 것

- 비동기 처리가 실제로 필요한 작업인지 확인한다.
- 비동기 처리 대상을 정한다. 예: 알림 발송, 이메일 발송, 외부 API 호출, 후처리 작업
- 사용자 요청 흐름에서 반드시 동기 처리해야 하는 작업과 분리한다.
- 트랜잭션 경계를 정한다.
- 실패 시 재시도 기준과 최대 재시도 횟수를 정한다.
- 중복 실행되어도 안전한지 확인한다.
- 동시성 제어가 필요한 자원을 정한다. 예: 재고, 포인트, 쿠폰, 예약 슬롯
- 사용할 동시성 제어 방식을 정한다. 예: 낙관적 락, 비관적 락, unique constraint, 분산 락
- 순서 보장이 필요한 작업인지 확인한다.
- 테스트 범위를 정한다. 예: 동시 요청, 중복 요청, 재시도, 롤백, 순서 보장
