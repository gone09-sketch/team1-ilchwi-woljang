# Indexing

## Status

이 문서는 프로젝트 고도화 단계에서 조회 성능 최적화가 필요해질 때 작성한다.

현재 단계에서는 도메인, 테이블, 조회 패턴이 확정되지 않았으므로 구체적인 인덱스 규칙을 정하지 않는다.

## 작성 전 확인할 것

- 실제 조회 패턴을 먼저 확인한다.
- 인덱스가 필요한 조건을 정한다. 예: where, join, order by, group by에 자주 쓰이는 컬럼
- 복합 인덱스 컬럼 순서를 정할 때 등치 조건, 범위 조건, 정렬 조건을 함께 고려한다.
- 중복 인덱스나 사용되지 않는 인덱스를 만들지 않는다.
- 쓰기 빈도가 높은 테이블에서는 인덱스 추가 비용을 확인한다.
- unique constraint와 일반 index의 목적을 구분한다.
- soft delete 컬럼이나 status 컬럼처럼 선택도가 낮은 컬럼의 단독 인덱스는 신중히 검토한다.
- 실행 계획 확인 기준을 정한다.
- 운영 데이터 규모를 가정하고 테스트한다.
- 테스트 범위를 정한다. 예: 주요 조회 쿼리, 정렬/페이징, 복합 조건, 실행 계획 변화
