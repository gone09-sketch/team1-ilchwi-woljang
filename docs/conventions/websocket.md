# WebSocket

## Status

이 문서는 프로젝트 고도화 단계에서 WebSocket이 필요해질 때 작성한다.

현재 단계에서는 WebSocket 사용 여부와 요구사항이 확정되지 않았으므로 구체적인 구현 규칙을 정하지 않는다.

## 작성 전 확인할 것

- WebSocket이 실제 요구사항인지 확인한다.
- 사용 목적을 구분한다. 예: 실시간 채팅, 알림, 상태 동기화, 대시보드 갱신
- 단방향 알림으로 충분한지, 양방향 통신이 필요한지 확인한다.
- 인증 방식을 정한다. 예: Handshake 인증, JWT 전달 위치, 만료 토큰 처리
- 메시지 형식을 정한다. 예: type, payload, timestamp, requestId
- 구독 경로와 발행 경로 네이밍을 정한다.
- 연결 끊김, 재연결, 중복 메시지 처리 기준을 정한다.
- 에러 메시지와 공통 응답 형식을 정한다.
- 메시지 저장 여부와 저장 범위를 정한다.
- 테스트 범위를 정한다. 예: 연결 인증, 구독 권한, 메시지 브로드캐스트, 예외 상황
