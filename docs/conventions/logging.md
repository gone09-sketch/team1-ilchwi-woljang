# Logging

## 목적

로그는 문제를 추적하고 운영 상황을 파악하기 위해 남긴다.

불필요하게 많은 로그나 민감 정보가 포함된 로그는 남기지 않는다.

## 기본 원칙

- 로그는 원인 추적에 도움이 되는 정보만 남긴다.
- 비밀번호, 토큰, 인증번호 같은 민감 정보는 로그에 남기지 않는다.
- 단순 디버깅용 로그를 남긴 채 커밋하지 않는다.
- 정상 흐름 로그와 에러 로그를 구분한다.
- 예외 로그는 원인을 추적할 수 있게 남긴다.

## 로그 레벨

- `debug`: 개발 중 상세 흐름 확인
- `info`: 주요 정상 흐름
- `warn`: 처리는 가능하지만 확인이 필요한 상황
- `error`: 요청 처리 실패, 예외 발생, 복구가 필요한 상황

## 예외 발생 시 로그 레벨 기준

- 예상 가능한 비즈니스 예외 중 운영 확인이 필요한 경우는 `warn`으로 남긴다.
- 단순 입력 오류처럼 운영 확인이 필요하지 않은 예외는 로그를 남기지 않을 수 있다.
- 예상하지 못한 서버 예외는 `error`로 남긴다.
- `error` 로그에는 반드시 예외 객체를 함께 전달한다.

## info 로그

`info` 로그는 중요한 정상 흐름에만 사용한다.

예시:

- 회원가입 성공
- 로그인 성공
- 주문 생성 성공
- 결제 승인 성공
- 주요 상태 변경 완료

모든 요청마다 의미 없는 `info` 로그를 남기지 않는다.

## warn 로그

`warn` 로그는 처리는 가능하지만 확인이 필요한 상황에 사용한다.

예시:

- 외부 API 일시 실패 후 재시도 예정
- 이미 처리된 요청 재수신
- 비정상적인 접근 시도
- 예상 가능한 예외지만 운영 확인이 필요한 상황

## error 로그

`error` 로그는 요청 처리 실패나 예상하지 못한 예외에 사용한다.

예외 객체를 함께 남겨 원인을 추적할 수 있게 한다.

```java
log.error("주문 생성 중 예외가 발생했습니다. orderId={}", orderId, e);
```

## 민감 정보

아래 정보는 로그에 남기지 않는다.

- 비밀번호
- Access Token
- Refresh Token
- 인증번호
- API Key
- 주민등록번호 등 개인 식별 정보

필요한 경우 일부 마스킹한다.

## 로그 메시지 작성 기준

로그 메시지는 어떤 상황이 발생했는지 알 수 있게 작성한다.

함께 남기면 좋은 값:

- 요청 식별자
- 사용자 식별자
- 리소스 식별자
- 외부 API 이름
- 처리 상태

## 피해야 할 Logging

- `System.out.println` 사용
- 민감 정보를 포함한 로그
- 의미 없는 반복 로그
- 예외 객체 없이 메시지만 남기는 `error` 로그
- 디버깅용 로그를 정리하지 않고 커밋하는 것
